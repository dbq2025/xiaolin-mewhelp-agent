**翻车与返工（三个真实发现，都是「先看它失败」逼出来的）**

1. **model.astream 会额外产出一个空串尾块**。我原以为「chunks 有几条就吐几条」，实测是 ['你', '好', '']。
   → 这解释了为什么 chat.py 必须过滤 falsy delta，否则会多发一个空的 token 事件给前端。已把测试名改成 ..._and_a_trailing_empty_one 把这个行为固定下来。

2. **pydantic 在构造时会复制 list 字段**。FakeChatModel(captured=seen) 之后 m.captured is seen 是 **False**，所以模型记录的是一份副本，测试拿不到。
   → 改用 Recorder dataclass 包装（任意类型按引用传递）。这是「断言 mock 行为」这类测试最容易踩的坑，值得记下来。

3. **基类 with_structured_output 对没实现 ind_tools 的模型直接抛 NotImplementedError**。
   → 读 langchain 源码确认契约是 self.bind_tools([schema], tool_choice="any") | PydanticToolsParser(...)，于是给假模型实现了 ind_tools，让 langchain 的 tool-call 解析与 pydantic 校验**真实执行**（而不是让假模型直接返回对象，那样 Task 8 的测试就等于自证）。
   → 连带发现：模型没产出 tool call 时，PydanticToolsParser **返回 None 而不是抛异常**。

**自我纠错（重要）**
上一条 ledger 里我写了「已回写计划 Task 7 / Task 8」——回写前核对计划原文后发现：Task 7 Step 3 本来就有 isinstance(chunk.content, str) and chunk.content 的空块过滤，Task 8 Step 3 本来就有 isinstance(result, AfterSalesRequest) 检查。
**也就是说这两条实测结论是计划本来就想对了，不是计划缺陷。** 我已更正 ledger，并在计划 Task 8 Step 3 下补了「执行期实测补充」，把 ind_tools 契约和 None 分支的必要性写成显式理由——否则后来者很可能把那个 isinstance 当多余的防御性代码删掉，然后静默返回 None。
