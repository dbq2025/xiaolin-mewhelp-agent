- **ModelScope SDK 起不来**：`snapshot_download` 要建 `C:\Users\dbq\.modelscope`，
  沙箱拒绝（`WinError 5`）。**修法**：不装 SDK，直接用它的 HTTP 文件接口
  （`/api/v1/models/.../repo/files` 列文件 + `/resolve/master/<file>` 下载）落到工作区
  `models/bge-m3`，顺带支持断点续传。
- **pymilvus 版本陷阱实锤**：`uv run --with pymilvus` 默认装 3.0.2，而官方兼容表要求

- **首次 probe 搜索返回空**：建集合后立刻 `upsert` 再 `search` 拿到 `data: [[]]`，
  误以为写入失败。根因是指标延迟 + 默认一致性级别。**修法**：改用
  `consistency_level='Strong'`，并记住 `get_collection_stats().row_count` 不可信
  （写完仍报 0），校验一律用 `query(count(*))` 或 `search`。

## 阶段 4.4 · Task 4 切分器完成（本章核心）

**用户关键原话**
> （沿用「A. Native」授权，中途未打断）

**关键产出**
- `app/knowledge/chunker.py`：`split_markdown` / `render_embed_text` / `Chunk`，
  17 条测试全绿；全量 **401 passed / 22 skipped**。
- 落地四个决定：
  1. 标题栈推出 `section_path` / `category` / `questions`，**FAQ 的标题就是真实问法**，
     于是「商品 FAQ」与「政策手册」共用同一条规则；
  2. 表格是**原子单元**，不参与按字符递归切；超 20 行或超长时按行切、每块复制表头，
     单行超长时宁可块超限也不掰两半；
  3. 重叠从「上一块尾部 ≤overlap 字里的**第一个**句末标点之后」开始 ——
     这就是「不留半截话」的实现；
  4. 关键条款只认显式标记，标记本身从标题与正文里删掉，不进向量化文本。

**被拒绝或纠偏**
- 计划里的重叠断言写成了 `startswith(tail.split("。")[-1]) or startswith("第")`，

4. **验收 2（中断重跑）**：
   - 中断：`--rebuild --max-chunks 5` → `pending=23 done=5 | milvus=5 → 不一致`
   - 重跑：`created=0 updated=0 skipped=22 vectors=23` →
     `pending=0 done=28 | milvus=28 → 一致`
   - 结论：漏向量化的 23 块被捡起补齐，且**没有重复建块**（`created=0`）。
5. 对话挖知识（真 LLM）：`batches=4 pairs=26 kept=23 discarded=3 ingested=23 vectors=23`；
   最终 `pending=0 done=51 | milvus=51 → 一致`（28 文档 + 23 挖掘）。
6. **端到端**：起服务问「邮费是多少」→ HTTP 200，调用 `query_faq`，
   答案「单笔订单满 99 元就包邮，没满 99 元收 10 元运费……」；
   落库的 tool payload：`{"ok":true,"keyword":"邮费是多少","count":5,...}`，
   首位命中是「满多少包邮？」→「满99元包邮」。
7. 全量测试（三组集成开关全开）：**507 passed，0 skipped**。

**被拒绝或纠偏**
- 验收 2 第一次跑出 `pending=18 done=10`：`--max-chunks 5` 被文档建库与 FAQ 建库
  **各用了一次**。用户直觉里的「本次最多补 5 条」是全局预算，改为
  `remaining_budget()` 跨步骤共享，并补了 4 条断言。
- 挖矿第一次 4 批全 400：`with_structured_output` 默认走 `json_schema`，DeepSeek 网关
  只支持 `function_calling`。仓库 `app/extract.py` 早已注释过这个坑，照抄并钉进测试。

**翻车与返工（一条真数据丢失）**
- **大表格丢行（Critical，已在验收前发现并修）**：首次建库打印
  `total=22 created=20`，说明有 2 块被当成同一行。根因：自然键是
  `(content_type, section_path, questions)`，而同一个 section 切出的多块共用同一个
  `section_path` —— 后一块**覆盖**前一块，售后手册 24 行表格的后半截静默消失，
  且建库**不报任何错**。
  修法：切分器给同节第 2、3…块在 `section_path` 后加 ` #n`（元数据、不进向量）。
  补了两条回归用例（切分层 + 仓库层），修后 `created=22/22`。
  教训：**幂等键必须包含「同一逻辑单元内的区分度」**，否则幂等会变成静默覆盖。
