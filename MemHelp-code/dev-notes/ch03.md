> 定时任务：「**A. CLI 脚本 + 外部调度器**（推荐）」
> 契约范围：「**A. 改 description，参数名与出参 JSON 一字不动**（推荐）」
> 去重口径：「**A. 字面归一化 + 向量余弦阈值**（推荐）」
> 演示会话：「**A. 造一批演示历史会话入库**（推荐）」
> 设计定稿：「**A. 全部认可，写 spec**」

**关键产出**

- **spec：`MemHelp-code/docs/superpowers/specs/2026-10-17-ch03-rag-design.md`**
  （12 节：流程分类/决策/环境实测/数据层/切分/建库/检索/挖矿/配置/测试/验收/交付/风险）。
- **路线选择**：新增 `app/knowledge/` 子系统 + `Protocol` 注入，否掉「塞进
  `repositories.py`」与「`langchain-milvus` VectorStore」两条路。
- **Context7 核对结果**（不是记忆）：
  - pymilvus 官方兼容表：Milvus 2.6.* ↔ pymilvus 2.6.X；实测本机 2.6.22 服务端 + 2.6.17 客户端。
  - 确定性 VARCHAR 主键 + `upsert` 是官方文档给的 RAG 重摄入做法，与「按主键幂等」需求同构。
  - `search(consistency_level='Strong')` 保证读己写，演示不用 sleep。
- **设计阶段就钉死的三处易错点**：
  1. 表格**不参与**按字符递归切（否则后半截丢表头，正是需求禁止的）；
  2. `--rebuild` 同时 drop 集合 + truncate 表，避免「表清了集合没清」的孤儿向量；
  3. 中断演示的正确预期是 `pending = 总块数 - 5`，不是 5。

**被拒绝或纠偏**

- 用户未推翻任何一节；六问全部选 A。
- 我自查 spec 时纠了自己 4 处：pymilvus 3.0.2 措辞（能连上，不是"不可用"）、
  表格与递归切的冲突、`--rebuild` 的清空范围、验收 2 的 pending 预期。
- 主动否掉两条用户的隐含选项：独立 embedding 服务（多一个常驻进程）、
  GPU（sm_120 版本风险），均已被用户以选 A 的方式确认。

**翻车与返工**

- **ModelScope SDK 起不来**：`snapshot_download` 要建 `C:\Users\dbq\.modelscope`，
  沙箱拒绝（`WinError 5`）。**修法**：不装 SDK，直接用它的 HTTP 文件接口
  （`/api/v1/models/.../repo/files` 列文件 + `/resolve/master/<file>` 下载）落到工作区
  `models/bge-m3`，顺带支持断点续传。
- **pymilvus 版本陷阱实锤**：`uv run --with pymilvus` 默认装 3.0.2，而官方兼容表要求
  2.6.X。**修法**：依赖引脚 `>=2.6,<3`，集成测试首条断言服务端版本。
- **首次 probe 搜索返回空**：建集合后立刻 `upsert` 再 `search` 拿到 `data: [[]]`，
  误以为写入失败。根因是指标延迟 + 默认一致性级别。**修法**：改用
  `consistency_level='Strong'`，并记住 `get_collection_stats().row_count` 不可信
  （写完仍报 0），校验一律用 `query(count(*))` 或 `search`。
