    ch05 要替换的是这条编排，而不是工具本身。
  - 五个工具已在 `app/tools/registry.py` 注册：`query_order` / `query_product` /
    `query_logistics` / `query_faq` / `create_ticket`；`executor.execute_tool` 负责
    参数校验、超时、重试、脱敏，**永不抛**。本章不新写业务工具。
  - 检索入口是 `app/knowledge/pipeline.py::RagPipeline.answer_context`：
    Query 理解 → 双路召回 → RRF → 重排 → ch04 的两道闸（阈值 + 模型自评）→ 编号证据。

  - 历史与落库：`messages` 表已有 `tool_calls` / `tool_traces` / `citations`；

- **环境实测**：
  - `langgraph 1.2.15`、`langgraph-checkpoint 4.3.0` 已随现有依赖安装；
    `langgraph.checkpoint.memory` 提供 `InMemorySaver` / `MemorySaver`。
  - **没有** `langgraph.checkpoint.sqlite` / `aiosqlite`：SQLite 持久化需要新增
    `langgraph-checkpoint-sqlite` 依赖（官方独立包），不是现有依赖自带。
- **Context7 核对（三条硬事实，先查后写）**：
  1. 带 checkpointer 的图必须传 `config={"configurable": {"thread_id": ...}}`；
     `thread_id` 是 checkpoint 的主键。
  2. 节点内可用 `get_stream_writer()` 发自定义事件，消费端用
     `astream(..., stream_mode="custom")` 接收（Python ≥3.11 异步节点可直接用）。
  3. `SqliteSaver` 位于 `langgraph.checkpoint.sqlite`，需要单独安装官方包；
     `InMemorySaver` 属于 `langgraph-checkpoint` 自带。
- **待用户确认的架构分叉**（见阶段 1）：checkpointer 形态、热身代码的落点、
  Agent 建议动作的产生方式、置信度闸的复用边界。

  交付物、风险、兼容）。

  `thread_id = session_id`；测试注入 `InMemorySaver`。
- **三处需求冲突的裁决写进 spec §2.1**：
  1. 「记下来留给飞轮」vs「飞轮入库留给后面」：只写 turn log + 复用 ch04 现有
     `low_confidence_questions` 池，不建新表；
  2. 「闲聊不花模型调用」vs「意图识别用 prompt 判七类」：明显寒暄走确定性快速通道
     （零调用），其余闲聊只付一次分类调用、不调用主力 Agent；
  3. 「复用第 2 章工具」vs「建工单必须用户点按钮」：Agent 工具集剔除
     `create_ticket`，只保留查询类 + `suggest_actions` 控制面工具。
- **spec 自查修了 5 处**（不是收尾补记）：
  1. 增加 `pending_messages`：agent 不直接提交 messages，`log_turn` 在 MySQL 成功
     后才提交，避免「页面没有、模型上下文却有」的半截回答；
  2. `log_turn` 增加 `last_committed_turn_id` 幂等，重试不会重复落库；
  3. 意图模型调用异常也走启发式兜底，且兜底默认 `after_sales`（business），
     不把真实问题误判成闲聊；
  4. 明确 HTTP 测试改为图路径，`chat_tools` 单测保留作回退参考；
  5. 补 `last_user_content(session_id)` 作为建单端点缺省描述。
