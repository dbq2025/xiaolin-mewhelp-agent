  - 纯文本请求返回「很高兴见你」。
  - `bind_tools([query_order])` 后问「帮我查一下订单 1001 到哪了」，模型**真实返回**：
    `[{'name': 'query_order', 'args': {'order_id': '1001'}, 'id': 'call_00_2EHqx1PKG5IOKSU91xE02756', 'type': 'tool_call'}]`
  - 结论：**三条验收标准我能自己实测**，不需要等用户填 `.env`（对比 ch01 阶段我前置声明过「无真实密钥、无法实测」）。
- **Context7 查证**（动手前查，不凭记忆）：
  - `@tool(args_schema=PydanticModel)` → `StructuredTool`；属性 `.name` / `.description` / `.args_schema`；
    可直接 `tool.ainvoke(tool_call_dict)`。
  - 回灌必须 `ToolMessage(content=..., tool_call_id=<模型给的 id>)`，id 对不上就报错。
  - `DeclarativeBase` + `Mapped` / `mapped_column` 是 SQLAlchemy 2.0 声明式写法；
    `sessionmaker(engine)` + `with Session() as s:` 为推荐用法。
  - async 工具优于 sync（sync 会被丢到线程池，多一层开销）。
- **沙箱实测发现**：`docker --version`（28.5.1）与 `docker compose version`（v2.40.3）都能跑，
  但任何连 daemon 的命令失败：
  `error during connect: ... open //./pipe/dockerDesktopLinuxEngine: Access is denied`，
  并伴随 `[sandbox: file access denied under workspace-write mode]`。
  → 根因是**沙箱不允许进程打开命名管道**，不是 Docker Desktop 没启动。
  起 MySQL 那步需要一次提权。

**翻车与返工**

1. 第一次想用 `uv run python -c "..."` 内联脚本探依赖版本，被 PowerShell 的引号转义搞崩
   （`SyntaxError: unterminated string literal`，`\"` 被原样传进 Python）。
   **修法**：改为写临时 `.py` 文件再 `uv run python <file>`。这个坑值得记 ——
   本仓库的中文/引号密集场景下，内联 `-c` 不可靠。
2. 探针脚本 `_probe_deps.py` / `_probe_llm.py` 用完即删，不留进仓库
   （避免它们被误当成正式代码并进入 lint/测试范围）。
