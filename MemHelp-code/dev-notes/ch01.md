**翻车与返工（三个真实发现，都是「先看它失败」逼出来的）**

1. **model.astream 会额外产出一个空串尾块**。我原以为「chunks 有几条就吐几条」，实测是 ['你', '好', '']。
   → 这解释了为什么 chat.py 必须过滤 falsy delta，否则会多发一个空的 token 事件给前端。已把测试名改成 ..._and_a_trailing_empty_one 把这个行为固定下来。

3. **基类 with_structured_output 对没实现 bind_tools 的模型直接抛 NotImplementedError**。
   → 读 langchain 源码确认契约是 self.bind_tools([schema], tool_choice="any") | PydanticToolsParser(...)，于是给假模型实现了 bind_tools，让 langchain 的 tool-call 解析与 pydantic 校验**真实执行**（而不是让假模型直接返回对象，那样 Task 8 的测试就等于自证）。
   → 连带发现：模型没产出 tool call 时，PydanticToolsParser **返回 None 而不是抛异常**。

**自我纠错（重要）**
上一条 ledger 里我写了「已回写计划 Task 7 / Task 8」——回写前核对计划原文后发现：Task 7 Step 3 本来就有 isinstance(chunk.content, str) and chunk.content 的空块过滤，Task 8 Step 3 本来就有 isinstance(result, AfterSalesRequest) 检查。

### 最大的一个坑：FastAPI 原生 SSE 满足不了「一个路径两种响应形态」

计划里（spec 第 7 节）写了用 fastapi.sse.EventSourceResponse，并预留了「无此模块就退回手工拼帧」的方案。实际执行下来发现：**模块在，但用不了**，我做了四组最小对照实验才定位清楚：

1. 
esponse_class=EventSourceResponse + yield ServerSentEvent → 正常（text/event-stream，帧格式规范）。这条没问题。
2. 手工构造 EventSourceResponse(...) 再 
eturn → Starlette 把它当普通内容二次编码，报 'ServerSentEvent' object has no attribute 'encode'。
3. 让路由是**普通 async 函数**、内部 
eturn 一个异步生成器（想借此同时支持 JSON 分支）→ FastAPI 拿到的是未 await 的协程，响应体为空。
4. 拆成**两条同路径路由**、各自用 guard 依赖分流 → 不行：Starlette 匹配到第一条「路径+方法」相同的路由就结束，guard 里抛 HTTPException 只会直接返回 422，**不会回落到第二条**。两种注册顺序都试了，必然有一半请求拿到 422。

结论：原生 SSE 只支持「路由函数本身是异步生成器」且只认 ServerSentEvent（yield 字符串会被编码成 data: "..."，yield Response 会被当成数据序列化）。

**最终方案**：退回计划预留的 fallback —— 普通 StreamingResponse + 自己编码 SSE 帧。编码逻辑抽成 app/sse.py::sse_frame（纯字符串处理），用 5 条测试单独钉住格式（帧结构、空行结尾、中文不转义、换行不撑破帧、data 是合法 JSON）。同时把「非流式」分支放在**路由函数里**直接 await 并返回 JSONResponse，这样上游错误发生在响应开始之前，能被 UpstreamError 处理器正常映射成 502/503。

**代价与收益**：代价是帧格式正确性要自己保证（已用测试兜住）；收益是 API 契约与三条验收标准**完全没变**。

**搬迁过程中发现并修掉的 3 个真实缺陷**

1. **`.env` 路径依赖当前工作目录**（搬迁前就存在，搬迁会放大它）
   `Settings.model_config` 里写的是 `env_file=".env"`，pydantic-settings 按 **CWD** 解析。
   实测：`chdir` 到 `MemHelp-code/` 后报 `ValidationError: 3 validation errors`。
   修法：`app/config.py` 用 `Path(__file__).resolve().parent.parent` 算绝对路径，并加测试断死「`ENV_FILE` 与 `app/` 同级」。**这是搬迁前必须修的**，否则从仓库根启动服务读不到配置。

2. **从仓库根跑 pytest 拿不到测试配置 —— 25 failed**
   pytest 把 rootdir 定在仓库根，**不会读** `MemHelp-code/pyproject.toml` 的 `[tool.pytest.ini_options]`，
   于是 `asyncio: mode=Mode.STRICT`（期望是 AUTO），异步测试整片失败。
   修法：加根级 `pytest.ini`（`testpaths` / `asyncio_mode=auto` / `pythonpath=MemHelp-code`），
   并在 `agent.md` 写明「两处测试配置必须同步改，否则会掩盖配置漂移」。
   修完：**从根跑 145 passed，从代码目录跑也是 145 passed**。

3. **从仓库根起服务 `ModuleNotFoundError: No module named 'app'`**
   `app` 包在 `MemHelp-code/` 下，从根直接 `uvicorn app.main:app` 找不到。
   修法（不引入 `PYTHONPATH` hack）：文档统一改为 `uv run --directory MemHelp-code ...` 或先 `cd` 进代码目录。已在 `agent.md` 与 `README.md` 写清三种可用方式。

**另一个沙箱残留（未解决，已记录）**
工作区根又出现 4 个锁死的 `pytest-cache-files-*/`（pytest 退出时新建又被收回权限，连重命名都被拒）。**这次复核出它的真实危害**：从仓库根跑 pytest 会把它们当测试目录去 scandir，直接 `PermissionError` 中断收集。
- 缓解：根级 `pytest.ini` 用 `testpaths = MemHelp-code/tests` 限定范围，不再扫根目录
- 清理：仍需切到**完全权限**才能删（`agent.md` 第 4 节已写明）

**我自己造成的一次返工（记录在案）**
