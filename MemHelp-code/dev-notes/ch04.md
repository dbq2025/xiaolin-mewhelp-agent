## 阶段 4.0 · Task 0 真机探针（四条硬结论）

**用户关键原话**

> 「就在 main 上做（与前几章一致，推荐）」

**关键产出（全部为探针实测，不是文档记忆）**

| # | 结论 | 影响 |
|---|---|---|
| 1 | `AnnSearchRequest(data=…, anns_field=…, limit=…, param={"metric_type": …}, expr=…)` 可用 | T3 照此实现 |
| 2 | **`hybrid_search` 的顶层 `filter` 被静默忽略**（不存在的品类仍返回 2 条）；顶层 `expr` 直接抛 `TypeError: got multiple values for keyword argument 'expr'` | 过滤必须挂到**每个** `AnnSearchRequest.expr` 上；已验证「不匹配品类 → 空」「组合条件 → 正确子集」 |
| 3 | `/rerank` 返回 `{id, results:[{index, relevance_score, document}], meta}`，`relevance_score` 是 0~1（实测 0.998 / 0.863） | 阈值 0.3 有标定空间；`return_documents=false` 时 `document` 为 null |
| 4 | **型号写法变体在 BM25 下全漏**：`XH-3000A` 命中 1.20；`xh-3000a` / `XH 3000A` / `XH3000A` 全部返回空 | chinese analyzer = jieba + cnalphanumonly，**不做大小写归一**，连字符与空格的切分也不同 |

**被拒绝或纠偏**

- 没有换分析器。用户把「内置 chinese analyzer」定死，探针暴露的问题用**检索侧型号归一**解决
  （T6：把 `[A-Za-z]{2,}-?\d{2,}[A-Za-z]?` 形的 token 统一成「大写 + 连字符」再进 `bm25_text`）。
  代价：语料里的型号必须写成「大写 + 连字符」，T12 的语料规范里写死这条。
- 计划与 spec 里「过滤用顶层 `filter` 参数」的措辞**是错的**，按探针改正（见下方返工）。

**翻车与返工**

- **顶层 `filter` 静默忽略**是最危险的一类失败：不报错、结果看起来正常，只是过滤没生效。
  如果把这条带进实现，验收「先过滤再检索」会**假通过**（过滤没生效但没人发现）。
  修法：改用 per-request `expr`，并在 T8 的测试里断言「两个 request 的 `expr` 都带上了」。
- 探针脚本第一版用 `settings.rerank_api_key` 直接崩（T1 还没做）。不改配置顺序，
  改成用现成的 `embedding_api_key` / `embedding_base_url` 发请求 —— 探针不该逼实现提前。
