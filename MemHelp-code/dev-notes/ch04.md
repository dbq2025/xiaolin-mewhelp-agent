## 阶段 1 · brainstorm 定稿（设计分两批获认可）

**用户关键原话**（7 个决策点 + 2 次设计确认）

> 接线形态：「**A. 沿用模型路由，query_faq 内核整体换掉（推荐）**」
> Milvus 集合：「**A. 原地重建 knowledge 集合，Milvus 存检索所需副本（推荐）**」
> 引用持久化：「**A. 追加 messages.citations JSON 列，存证据快照（推荐）**」
> reranker 跑法：「**A. 复用硅基流动同一把 Key 调云端 /rerank（推荐）**」
> 评估集与语料：「**A. 新增型号语料 + 48 条四桶评估集，锚串标 gold（推荐）**」
> faith_cases 范围：「**A. 落表 + 最小查询/处置端点，不做页面（推荐）**」
> 入池口径：「**A. 检索低置信 + 模型自评 两个入口都开（推荐）**」
> 第 1–4 节：「**认可，继续给第 5–8 节（推荐）**」
> 第 5–8 节：「**全部认可，写 spec（推荐）**」

**关键产出**

- **spec：`MemHelp-code/docs/superpowers/specs/2026-10-17-ch04-hybrid-retrieval-design.md`**
  （17 节：流程分类/决策/勘查与实测/数据层/Query 理解/混合检索/RRF/重排/过滤/引用编排/
  拒答与入池/Prompt 与负面知识/评估/前端/配置/测试/验收/交付/风险）。
- **架构定稿**：模型仍决定是否检索；`query_faq` 内核换成
  `改写 → 双路 50 → RRF 20 → 重排 10 → 自评 → 编号证据`；证据编号按**相关度**固定，
  塞进 prompt 的顺序按**首尾编排** `[1,3,5,7,9,10,8,6,4,2]`。
- **两条结构性决定**（不靠模型自觉）：
  1. 拒答**短路**：证据不足时编排层不发第二次模型调用，直接吐固定话术 → 验收 4 不依赖模型意愿；
  2. 引用**后端反解**：正文 `[n]` 由后端解析并删掉越界编号的映射，模型多写角标不会让回答消失。
- **评估口径**：48 条 = 四桶 × 12（10 正 + 2 负）；gold 用唯一锚串在跑的时候解析成 chunk_id
  并断言唯一；检索段四策略全跑，生成段默认两策略（`--all-strategies` 可全跑），
  没跑的格子写「—」不填 0。
- **口径变更记录**：ch03「Milvus 不存第二份真相」→ ch04「Milvus 是检索索引副本，
  MySQL 仍是原文权威，改原文必须重建索引」。

**被拒绝或纠偏**

- 用户三次询问里都没有要求改设计，全部认可。
- 我在第 1 批里主动把「模型可能根本不调 `query_faq` 就作答」这条**残留风险**摊开写进 spec
  §9.6，没有掩饰；对策是 Prompt 强约束 + 把「未检索就答率」当指标统计。

**翻车与返工**

- 暂无（本阶段没有代码改动）。唯一一次返工是自查 spec 时把「负面知识清单」的边界写清楚：
  **引用知识库里的规则数字（允许，须带 `[n]`）** 与 **对本笔订单做承诺（禁止）** 是两件事，
  初稿把两者混在一起写，会导致评估集里「退款 3 个工作日」这类题被误判成违禁。
- **spec 自查又修了 4 处**（写在提交里，不是收尾时补的）：
  1. gold 锚串初稿要求「恰好命中 1 块」，但 `赔付` 这类锚串天然跨多个 chunk →
     改成「锚串命中 ≥1、gold 取并集、命中 >3 块告警」，否则评估集自己跑不起来；
  2. 阈值标定初稿只写「取中点」，正负样本分数**重叠**时中点无意义 →
     补 5 分位 / 95 分位的降级口径，并要求把重叠区间报出来；
  3. 两道闸漏了适用范围 → 明确「只在线上 `hybrid_rerank` 生效，评估跑检索不做拒答」，
     否则评估量到的就不是四策略的真实表现；
  4. 交付物漏了工具契约三个文件（`tools/knowledge.py` / `registry.py` / `schemas.py`），
     `category` 可选参数要落在这三处。
