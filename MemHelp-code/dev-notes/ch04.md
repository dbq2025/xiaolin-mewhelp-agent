> 第 5–8 节：「**全部认可，写 spec（推荐）**」

**关键产出**

- **spec：`MemHelp-code/docs/superpowers/specs/2026-10-17-ch04-hybrid-retrieval-design.md`**
  （17 节：流程分类/决策/勘查与实测/数据层/Query 理解/混合检索/RRF/重排/过滤/引用编排/
  拒答与入池/Prompt 与负面知识/评估/前端/配置/测试/验收/交付/风险）。
- **架构定稿**：模型仍决定是否检索；`query_faq` 内核换成
  `改写 → 双路 50 → RRF 20 → 重排 10 → 自评 → 编号证据`；证据编号按**相关度**固定，
  塞进 prompt 的顺序按**首尾编排** `[1,3,5,7,9,10,8,6,4,2]`。
- **两条结构性决定**（不靠模型自觉）：
  1. 拒答**短路**：证据不足时编排层不发第二次模型调用，直接吐固定话术 → 验收 4 不依赖模型意愿；
  2. 引用**后端反解**：正文 `[n]` 由后端解析并删掉越界编号的映射，模型多写角标不会让回答消失。
- **评估口径**：48 条 = 四桶 × 12（10 正 + 2 负）；gold 用唯一锚串在跑的时候解析成 chunk_id
  并断言唯一；检索段四策略全跑，生成段默认两策略（`--all-strategies` 可全跑），
  没跑的格子写「—」不填 0。
- **口径变更记录**：ch03「Milvus 不存第二份真相」→ ch04「Milvus 是检索索引副本，
  MySQL 仍是原文权威，改原文必须重建索引」。
