**你的关键产出**

- 判定本章为**架构级**任务，走完整 Superpowers 流程（brainstorm → spec → plan → 逐 Task TDD →

**我拒绝或纠偏了什么**

- 我没有接受「照抄教学文档里的公式」：文档只给结论（滑窗 5650、层1 3954、层2 1695），没给

- 我没有直接沿用 `count_tokens_approximately(chars_per_token=4.0)`：实测 50 字中文（28 个汉字）
  只算 17 tokens，真实约 40–50 —— 低估近 3 倍，方向是**危险**的（会撑爆窗口）。改为可注入的
  校准计数器，且预算与计数器必须同源改。

**翻车与返工**

  C:\Users\dbq\AppData\Local\uv\cache` / `failed to open file ...sdists-v9\.git: 拒绝访问。

## 阶段 1 · brainstorm 定稿（2026-10-20）

**我这一步发的关键原话**

> 「选A,另外请你用 Superpowers 模式,不要总是停下来,你直接前端弹出候选框就好了.」

**你的关键产出**

三个候选方案，各自讲清代价：

- **A（我推荐、你选的）**：把 `app/context.py` 升级成「预算 + 三层装配」的唯一权威，拆成
  `app/context/` 包（`tokens.py` / `budget.py` / `layers.py` / `assemble.py`），全部纯函数，
  输入是纯数据（`MessageRow` 列表 + 两个 int 锚点），不碰 DB、不碰网络，可完全离线测；
  摘要任务独立成 `app/agent/summarizer.py`（`asyncio.create_task` + 会话级 in-flight 去重 +
  任务自己开 Session），天然「不阻塞本轮」。
- **B（否决）**：摘要做成图节点 + 条件边，靠 checkpointer 驱动。致命点：图节点**同步推进**
  turn —— 要么阻塞本轮（违反验收 4），要么用 `interrupt()` 伪装后台（语义错位，且摘要是
  辅助动作，不该让用户点「继续」）。而且摘要失败会拖成 error 分支，把主链拉红。
- **C（否决）**：裁剪下推到 repository / SQL（按 id 区间取、`LIMIT` 切）。致命点：规则截短是
  **表达层**的事，而 token 预算要等 Python 算完才知道切到哪 —— 权威被劈成两半，早晚对不上。

**我拒绝或纠偏了什么**

- 拒绝把 `summary` 列留在 `conversations` 里（原 DDL 的方案）。理由：一段摘要是一行事实
  （有起止 id、有段号、有耗时），塞进会话壳的单个 TEXT 列就只能「覆盖写」，而需求明确要
  「一段段攒、压完不回头重写」—— 覆盖写等于每轮都对同一批事实再做一次有损压缩。
- 拒绝「摘要单独占一条 SystemMessage」。理由：上游模板会把所有 system 上提合并渲染，一旦
  梗概进 system，工具定义就被挤到可变内容之后，前缀缓存整段作废 —— 这是**成本**，不是风格。

**翻车与返工**

- 无代码翻车。一处判断返工：一开始想把「层 2 攒够了」的判据写成「层 2 条数 > N」，实测发现
  工具结果根本不落 `messages` 表（`persist.py` 只落 user/assistant/tool 三类行，而 tool 行是
  回灌用的，不进层 2 的可见历史），**数条数看不见它涨**。改成按 token 用量触发，这条后来写进
  spec §2.3。
