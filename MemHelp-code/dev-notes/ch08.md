- 兼容路径最初写在 `spec = table.get(name)` 之后，`query_order` 直接命中内置真工具，假工具被忽略：`test_successful_execution_reports_duration` 实测 9ms（真库查询），不是注入的 20ms sleep。改成 `resolve` 优先后才恢复。

### 用户关键原话

### 关键产出

- `app/tools/mcp_client.py`：
  - `connections_from_settings(settings)`：`mcp_enabled` 关闭时返回空表；打开时按 `mcp_logistics_url` / `mcp_aftersales_url` / `mcp_timeout_seconds` 拼 `transport="streamable_http"`。

  - `McpToolProvider(connections, *, read_only_servers, timeout=3.0, client=None)`：懒构造 `MultiServerMCPClient`；`discover()` 逐 Server、单个失败沿用该 Server 旧缓存、全部失败整体沿用；不在白名单的 Server **连 `get_tools` 都不调用**，直接 warning 拒绝。
  - `_schema_of`：dict 原样用，Pydantic 用 `model_json_schema()`，坏的/缺的退回 `{"type":"object","properties":{}}`。
  - `unwrap_mcp_result(raw)`：把 `[{"type":"text","text":"{...}"}]` 摊平成文本；执行引擎对 `source=="mcp"` 的结果先过这一层。
- `tests/test_mcp_client.py` 7 passed（来源/服务器/只读/schema 映射、单 Server 失败隔离、失败保留缓存、白名单整站拒绝、无 schema 兜底、content block 解包）。

- 全量 1102 passed, 41 skipped。

### 被拒绝 / 纠偏

- 白名单按 **Server** 而不是按工具：只要 Server 不在 `mcp_readonly_servers` 里就整站拒绝。理由与计划 D4 一致——外部 Server 自称的 `readOnlyHint` 不可信，按工具逐个信任等于把权限判断交给对方。
