### 关键产出

- 上下文勘察：主链路 `RagPipeline.retrieve_only()` 不调自评；ch04 的 `self_check` 落池只在旧 `app/chat_tools.py` 路径；`app/agent/graph.py` 的 `_confidence_gate` 是 ch05 最简阈值版；👎 只在 `web/app.js` 写 localStorage；`messages.citations` 不含分数。
- Context7 + 实测核对：
  - Langfuse 自部署 v4（web + worker + Postgres + ClickHouse + Redis + MinIO）已拉起，`http://127.0.0.1:3000`，server 4.69.0。
  - `langfuse==5.0.4`：`from langfuse.langchain import CallbackHandler`；trace 级属性用 `propagate_attributes(tags=..., metadata=...)`。
  - Metrics API v2 **不支持 `metadata.*` 维度**（400），但支持 `tags` → 意图成本改用 `tags=["intent:<x>"]` 聚合。
  - `compile(...).with_config({"callbacks":[...]})` 仍返回 `CompiledStateGraph`，`aget_state` / `checkpointer` / custom stream 全保留（四个探针脚本在 `scripts/spike_*.py`）。
- 设计文档：`docs/superpowers/specs/2026-10-24-ch09-observability-flywheel-design.md`（15 项决策 + 数据模型 + 测试策略）。
- 关键决策：主图在闸通过后补 `SufficiencyJudge` 自评入口；三入口入池都带 `retrieved_chunks` 快照；飞轮同步处理；置信度闸用三特征逻辑回归 + ch04 评估集留一法校准，LOO balanced accuracy < 0.70 就不发布模型、退回 ch05 阈值闸。

### 被拒绝 / 纠偏

- 用户否掉「异步飞轮」（先入池、后台再标准化），选同步：刷新审核页立刻可见；代价是每轮多 1–3 秒。
- 用户否掉「校准不达标也硬上模型」，选退回阈值闸 + 报告说明。
- 自我纠偏：不能直接改 `retrieve_only` 加阈值逻辑 —— 它在低分时返回空证据，Top1/Top2 分差与有效证据数就没了；改为新增 `retrieve_for_gate()`，旧接口保留给工具路径与既有测试。
- 自我纠偏：意图成本不能按 `metadata.intent` 聚合（实测 400），必须用 tags；trace 详情里仍保留 `metadata.intent` 供排查。

### 翻车与返工

- 沙箱里 `docker ps` 报 `Access is denied ... dockerDesktopLinuxEngine`；用户授权后切 `danger-full-access` 才连上 Docker。容器起来后策略已切回 `workspace-write`。

## 阶段 4 · 任务 3 完成：证据置信度模型

### 用户关键原话

- 「检索证据置信度低：把 ch05 那道最简版置信度闸升级成正式的置信度检查，拿检索和精排结果算 evidence_confidence（精排 Top1 的相关性分、有效证据数量、Top1 和 Top2 的分差这些信号），阈值拿 ch04 评估集校准、不拍脑袋定」
- 「校准兜底选择：退回 ch05 阈值闸并写报告」（设计评审时的选择）

### 关键产出

- 新建 `app/agent/evidence_confidence.py`：
  - `EvidenceFeatures(top1, top2, margin, effective_count)`；`features_from_scores()` 把降序分数压成三信号，有效证据数 = 分数 ≥ `max(0.1, top1*0.5)` 的条数。
  - `ConfidenceModel(weights, intercept, threshold, mean, std, version)`：`score()` 先按训练集均值/标准差标准化再过 sigmoid，`passes()` 比阈值。
  - `fit_logistic()`：纯 Python 固定 3000 轮、lr 0.1、L2 1e-3，零初始化；样本必须含正负两类。
  - `calibrate_loo()`：逐样本留出训练并预测，阈值 0.05–0.95 扫描取 balanced accuracy 最大（并列取更接近 0.5），最后全量重训；报告含 `balanced_accuracy`、`confusion`、`threshold`、`probabilities`。
  - `model_to_dict` / `model_from_dict` / `load_model`：JSON artifact；缺失、坏 JSON、维度不符一律 `None`。
- `app/config.py` 增 `evidence_confidence_model="evals/ch09_confidence_model.json"`；`.env.example` 同步 `EVIDENCE_CONFIDENCE_MODEL`。
- `tests/test_ch09_confidence.py` 8 条：特征/空输入/合成数据可分/LOO 混淆矩阵/落盘往返/坏文件/维度校验/单类样本报错。

### 被拒绝 / 纠偏

- 计划里的 LOO 测试样例口径保留，但逻辑回归样例改成正例「高分 + 分差 0.3」、负例「低分 + 分差 0.01」：plan 原样例（正例分差 0.05、负例分差 0.2）会让模型学到「分差越大越不可信」，是样例自相矛盾，不是实现缺陷。
- `tmp_path` 在沙箱退出后会报 `PermissionError`，按仓库既有约定改用工作区内 `.uv-cache/ch09-confidence-fixtures/<uuid>` 并在 fixture 里清理。

### 翻车与返工

- 第一次跑测试：1 failed（合成数据方向反了）+ 2 errors（`tmp_path` 权限）。先确认是样例与沙箱问题，再调样例/夹具，没有放宽模型断言。
- 全量回归：1138 passed, 43 skipped。
