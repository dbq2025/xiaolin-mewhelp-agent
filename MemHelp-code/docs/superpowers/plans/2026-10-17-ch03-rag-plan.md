# ch03 向量语义检索 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `query_faq` 的内部实现从 `LIKE` 关键词查表换成 BGE-M3 + Milvus 的 dense 向量语义检索，并补齐离线建库（结构感知切分 + 对话挖知识）与 MySQL/Milvus 双写落库。

**Architecture:** 新增 `app/knowledge/` 子系统，把「切分 / 嵌入 / 向量库 / 建库编排 / 检索 / 挖矿」各拆成一个文件，依赖用 `Protocol` 声明，测试注入假实现即离线可跑。MySQL 是原文权威源（`knowledge_chunks`），Milvus 只存 `id + vector`，检索拿 id 回 MySQL 取原文。`query_faq` 的入参名与出参 JSON 一字不动，只换内部实现与 description。

**Tech Stack:** Python 3.12 / FastAPI / SQLAlchemy 2.1 + PyMySQL / Milvus 2.6.22 + pymilvus 2.6.x / BGE-M3 (sentence-transformers, CPU) / LangChain 1.4 + langchain-core / pytest

**Spec:** `MemHelp-code/docs/superpowers/specs/2026-10-17-ch03-rag-design.md`

## Review Focus

以下五类输入/失效模式 spec 提到了但没人天然会测，每个都必须在拥有该代码的任务里补测试：

1. **空或纯标点查询**（模型可能传 `"？"` 或 `" "`）：`query_faq` 必须返回 `count=0` 的正常 JSON，不得抛异常变成 `ok=false`。（Task 9）

- [ ] **Step 3: 实现**

沿用本文件既有纪律：`async def` 包 `_run(self._method, ...)`；返回纯 dataclass，不返回 ORM 实例。

- `upsert_chunk`：`select(KnowledgeChunk).where(content_type==, section_path==, questions==)`；
  无行 → INSERT（`vectorize_status="pending"`）返回 `(id, True)`；
  有行且 `answer` 相同 → 不动，返回 `(id, False)`；
  有行且 `answer` 不同 → UPDATE `answer`、`vectorize_status="pending"`、`vector_id=None`，返回 `(id, False)`。
  `section_path` 为空时用 `""` 参与比较（MySQL 里 `NULL != NULL` 会让幂等失效）。
- `link_neighbours`：按传入顺序，把第 i 个的 `next` 指向 i+1、第 i+1 的 `prev` 指向 i，两次 `UPDATE` 后一次 `commit`。
- `list_pending`：`where(or_(vectorize_status=="pending", vector_id.is_(None))).order_by(KnowledgeChunk.id).limit(...)`。
- `mark_done`：逐对 `UPDATE`（批内一条 `commit`），`vector_id` 与 `vectorize_status="done"` 同时写。
- `truncate`：`DELETE FROM knowledge_chunks`（**不用** `TRUNCATE`，MySQL 的 `TRUNCATE` 会被外键约束拒绝；`DELETE` 后 `ALTER TABLE ... AUTO_INCREMENT=1` 可选，本章不依赖自增复位）。
- `QaStagingRepository.mark`：`update().where(id.in_(ids)).values(status=...)`。
- `FaqRepository.list_all`：`select(Faq).order_by(Faq.id)`。

`split_markdown` 的算法（按此顺序，签名与测试已定，只补测试判不出的细节）：

1. 预处理：`text.lstrip("\ufeff").replace("\r\n", "\n").replace("\r", "\n")`。
2. 用 `re.finditer(r"^(#{1,6})[ \t]+(.+)$", text, re.M)` 找标题，按行号切出 (level, title, body)。
3. 维护标题栈（`list[tuple[int, str]]`）：遇到 level L 先 pop 掉所有 level ≥ L 的项，再 push 当前。
   - `section_path = " / ".join(t for _, t in stack)`
   - `category = " / ".join(t for _, t in stack[:-1])`，空则退化为文档一级标题（栈底）。
   - `questions` = 当前标题去掉 `KEY_CLAUSE_TITLE_SUFFIX` 后的文本；`is_key_clause` = 标题含该后缀。
4. 正文按「原子块」序列化：连续 `|` 行聚成表格块（含表头与分隔行），其余按空行分段。
   表格块若「整表 ≤ max_chars 且数据行 ≤ 20」→ 单个原子块；否则按行切成多个原子块，
   每块内容 = `f"（接上表：{questions}）\n{header}\n{sep}\n{rows}"`。
5. 贪心合并原子块至 `max_chars`；单原子块超长时递归：
   按 `SENTENCE_ENDINGS` 切句 → 贪心拼；单句仍超长 → 按 `max_chars` 硬切。
6. 块间重叠：**只在同一 section 因长度被切开时**，后块前缀 = 前块尾部最多 `overlap` 字，
   并用 `rfind` 回退到最近的 `SENTENCE_ENDINGS` 或换行之后（找不到则不复述）。
7. `KEY_CLAUSE_MARKER` 出现在 section 正文里也算关键条款，并在 `answer` 中删除该标记行。
8. 跳过 `answer.strip() == ""` 的 section。

```python
import re


class _FakeStructured:
    """按 prompt 里的 `### 会话 <id>` 标记回填 session_id，顺带钉住 prompt 格式。"""
    def __init__(self, pairs_factory): self.pairs_factory = pairs_factory
    async def ainvoke(self, messages):
        text = str(messages)
        sid = re.search(r"### 会话 (\S+)", text).group(1)
        return ExtractionBatch(pairs=self.pairs_factory(sid))


class _FakeLlm:
    def __init__(self, pairs_factory): self.pairs_factory = pairs_factory
    def with_structured_output(self, schema): assert schema is ExtractionBatch; return _FakeStructured(self.pairs_factory)


class _TopicEmbedder:
    """同一话题 → 同一向量（cos=1）；不同话题 → 正交（cos=0）。"""
    async def embed(self, texts):
        return [[1.0, 0.0, 0.0, 0.0] if "邮费" in t else [0.0, 1.0, 0.0, 0.0] for t in texts]


async def _seed(session, n):
    from app.db.repositories import Repositories
    repos = Repositories.from_session(session)
    for i in range(n):
        cid = await repos.conversations.upsert_by_session(f"demo-ch03-{i:03d}", "u")
        await repos.messages.append(cid, role="user", content=f"邮费是多少？第{i}次")
        await repos.messages.append(cid, role="assistant", content="满 99 元包邮。")
    return repos


def _one_pair(sid):
    return [ExtractedQa(session_id=sid, question="邮费是多少", answer="满 99 元包邮")]


async def test_batches_are_sized_and_batch_no_is_recorded(sqlite_session):
    repos = await _seed(sqlite_session, 10)
    report = await mine_conversations(repositories=repos, llm=_FakeLlm(_one_pair),
                                      embedder=_TopicEmbedder(), batch_size=4)
    assert report.batches == 3
    rows = await repos.qa_staging.list_by_status("extracted")
    assert len(rows) == 3 and len({r.batch_no for r in rows}) == 3


async def test_failed_batch_writes_nothing_and_others_continue(sqlite_session):
    calls = {"n": 0}
    class _FlakyLlm(_FakeLlm):
        def with_structured_output(self, schema):
            calls["n"] += 1
            n = calls["n"]
            if n == 2:
                class _Boom:
                    async def ainvoke(self, messages): raise RuntimeError("upstream 500")
                return _Boom()
            return _FakeStructured(_one_pair)
    repos = await _seed(sqlite_session, 10)
    report = await mine_conversations(repositories=repos, llm=_FlakyLlm(_one_pair),
                                      embedder=_TopicEmbedder(), batch_size=4)
    assert len(report.failed_batches) == 1
    rows = await repos.qa_staging.list_by_status("extracted")
    assert len(rows) == 2                      # 第 1、3 批各 1 行，第 2 批 0 行
    assert report.failed_batches[0] not in {r.batch_no for r in rows}


async def test_empty_llm_result_writes_nothing_and_does_not_crash(sqlite_session):
    repos = await _seed(sqlite_session, 3)
    report = await mine_conversations(repositories=repos, llm=_FakeLlm(lambda sid: []),
                                      embedder=_TopicEmbedder(), batch_size=3)
    assert report.pairs_written == 0
    assert await repos.qa_staging.count_by_status() == {}


async def test_blank_and_duplicate_pairs_are_filtered_before_staging(sqlite_session):
    def pairs(sid):
        return [ExtractedQa(session_id=sid, question="", answer="x"),
                ExtractedQa(session_id=sid, question="邮费是多少？", answer="满 99 包邮"),
                ExtractedQa(session_id=sid, question="邮费是多少", answer="满 99 包邮")]
    repos = await _seed(sqlite_session, 1)
    await mine_conversations(repositories=repos, llm=_FakeLlm(pairs), embedder=_TopicEmbedder(), batch_size=1)
    rows = await repos.qa_staging.list_by_status("extracted")
    assert len(rows) == 1 and rows[0].question == "邮费是多少？"


async def test_dedupe_is_literal_then_semantic(sqlite_session):
    repos = Repositories.from_session(sqlite_session)
    await repos.qa_staging.add_rows([
        {"batch_no": "b1", "source_ref": "s1", "question": "邮费是多少", "answer": "满 99 包邮"},
        {"batch_no": "b1", "source_ref": "s2", "question": "邮费 是多少？", "answer": "满 99 包邮"},
        {"batch_no": "b2", "source_ref": "s3", "question": "寄回来要我付邮费吗", "answer": "满 99 包邮"},
    ])
    report = await dedupe_and_ingest(repositories=repos, embedder=_TopicEmbedder())
    assert (report.kept, report.discarded) == (1, 2)
    kept = await repos.qa_staging.list_by_status("kept")
    assert len(kept) == 1 and kept[0].questions.count("\n") == 2      # 三条问法合并
    assert await repos.knowledge.count_by_status() == {"pending": 1, "done": 0}


async def test_second_run_skips_already_mined_sessions(sqlite_session):
    repos = await _seed(sqlite_session, 2)
    await mine_conversations(repositories=repos, llm=_FakeLlm(_one_pair),

    before = await repos.qa_staging.count_by_status()

                             embedder=_TopicEmbedder(), batch_size=2)

    await mine_conversations(repositories=repos, llm=_FakeLlm(_one_pair),
                             embedder=_TopicEmbedder(), batch_size=2, force=True)
    assert await repos.qa_staging.count_by_status() != before
```

- `dedupe_and_ingest`：取 `status="extracted"` 全量 → 归一化字面去重 →
  逐条与已保留问题算余弦（`embedder.embed` 一次批量拿全部向量）→ ≥ 阈值判同义 →

  入 `knowledge_chunks`（`content_type="mined"`、`category="对话挖掘"`、
  `section_path=f"对话挖掘 / {source_ref}"`、`questions=<合并问法>`、`answer=<答案>`）。
  **本函数不向量化** —— CLI 在它之后调 `vectorize_pending`，两件事分开才好各自重跑。
